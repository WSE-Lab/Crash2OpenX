# CARLA 场景运行逻辑说明

> 基于 `src/demo.py` 入口，梳理场景加载、路线确定、ADS 加载、停止条件与指标收集的完整流程。

---

## 一、整体架构

```
demo.py
  └── ScenarioRunner (scenario_runner_local.py)
        ├── OpenScenarioConfiguration (openscenario_configuration.py)  # 解析 .xosc 文件
        ├── OpenScenario (open_scenario.py)                            # 构建行为树
        └── ScenarioManager (scenario_manager_local.py)                # 驱动仿真 tick
              ├── AgentWrapper (srunner/autoagents/agent_wrapper.py)   # 包装 ADS
              └── DataCollector (data_collector.py)                    # 数据收集
```

---

## 二、入口：demo.py

### 启动流程

```
1. 解析命令行参数（host、port、scenario、sync 等）
2. 用 xml.etree.ElementTree 解析 .xosc 文件得到 xml_tree
3. 创建 DataCollector（场景名取自 .xosc 文件名）
4. 创建 ScenarioRunner(args, xml_tree)
5. 调用 scenario_runner.run()
6. 结束后调用 data_collector.save_data() 保存 JSON 数据
7. 最终 scenario_runner.destroy() 清理资源
```

**关键参数**

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--scenario` | `001_Zoox_April_11_2025.xosc` | OpenSCENARIO 文件路径 |
| `--host` | `localhost` | CARLA 服务器地址 |
| `--port` | `2000` | CARLA 服务器端口 |
| `--sync` | `True` | 同步模式（固定帧率 20Hz） |
| `--collect-data` | `True` | 是否启用数据收集 |
| `--no-rendering` | `False` | 启用 CARLA `no_rendering_mode`，不渲染画面也能跑测试 |
| `--record-video` | `False` | 根据采集轨迹生成俯视视频 `trajectory_video.mp4` |

## 三、场景配置解析：OpenScenarioConfiguration

**文件**：`src/openscenario_configuration.py`

`ScenarioRunner._run_openscenario()` 中实例化该类，完成对 `.xosc` 的全面解析：

### 3.1 XSD 校验

```python
xsd_file = "../scenario_runner/srunner/openscenario/OpenSCENARIO.xsd"
xsd.validate(self.xml_tree)  # 验证 OpenSCENARIO 1.0 格式
```

### 3.2 参数替换（`_set_parameters`）

读取 `<ParameterDeclarations>` 并将所有 `$参数名` 引用替换为实际数值，支持自定义参数覆盖。

### 3.3 Catalog 加载（`_load_catalogs`）

加载 `<CatalogLocations>` 中定义的外部 catalog 文件（Vehicle/Controller/Pedestrian/Route 等），以便后续引用车辆模型、控制器等。

### 3.4 地图加载（`_set_carla_town`）

从 `<RoadNetwork><LogicFile filepath="..."/>` 提取地图名称：
- 若为 `.xodr` 文件：调用 `client.generate_opendrive_world()` 生成地图
- 若为地图名称（如 `Town05`）：调用 `client.load_world(town)` 加载内置地图

### 3.5 Actor 信息提取（`_set_actor_information`）

遍历 `<Entities>` 中的 `<ScenarioObject>`，区分：
- **ego_vehicle**：`<Property name="type" value="ego_vehicle"/>` → 加入 `self.ego_vehicles`
- **其他 Actor**：车辆/行人/静态障碍物 → 加入 `self.other_actors`

每个 Actor 的初始位置从 `<Init><Actions><Private entityRef="...">` 的 `<Position>` 节点解析，初始速度从 `<SpeedAction>` 中读取。

## 四、路线确定逻辑

路线在 `.xosc` 的 `<Storyboard><Init>` 和 `<Story>` 两个部分定义，由 `open_scenario.py` 在构建行为树时处理。

### 4.1 初始化阶段的路线（`_create_init_behavior`）

解析每个 Actor 的 `<Private>` 初始化动作，若包含 `<RoutingAction>`：

| 动作类型 | 说明 |
|----------|------|
| `AssignRouteAction` | 通过 `<Waypoint>` 列表指定途经点，调用 `OpenScenarioParser.get_route()` 提取 |
| `FollowTrajectoryAction` | 通过 `<Trajectory>` 精确时间轨迹，提取 waypoints + 时间序列 |
| `AcquirePositionAction` | 指定单一目标位置，以"fastest"模式到达 |

路线最终被封装为 `ChangeActorWaypoints` 行为原子，Actor 会按 waypoints 导航。

### 4.2 故事阶段的路线（`_create_behavior`）

`<Story>` → `<Act>` → `<ManeuverGroup>` → `<Maneuver>` → `<Event>` → `<Action>` 层层嵌套。
`OpenScenarioParser.convert_maneuver_to_atomic()` 将各类 Action（速度变换、车道变换、路线更新等）转换为 py_trees 行为原子，运行时通过 `scenario_tree.tick_once()` 驱动。

**路线变更触发条件**：每个 Event 有 `<StartTrigger>` 条件（如到达某位置、经过某时间、与其他 Actor 的相对距离等），条件满足时对应的 Action 才会执行。

## 五、ADS（自动驾驶代理）加载

### 5.1 接口定义

基类：`srunner/autoagents/autonomous_agent.py`，需实现：

```python
class MyAgent(AutonomousAgent):
    def setup(self, path_to_conf_file): ...      # 初始化模型、加载配置
    def sensors(self) -> list: ...               # 返回传感器配置列表
    def run_step(self, input_data, timestamp):   # 每帧决策，返回 carla.VehicleControl
        ...
```

### 5.2 加载方式

在 `ScenarioRunner.__init__` 中，`self.agent_instance = None`（当前 demo 未加载 ADS）。
若要加载 ADS，需在 `.xosc` 的 `<ControllerAction>` 中通过 `<AssignControllerAction>` 指定 Python 模块路径和参数：

```xml
<ControllerAction>
  <AssignControllerAction>
    <Controller name="MyADS">
      <Properties>
        <Property name="module" value="my_agent_module"/>
      </Properties>
    </Controller>
  </AssignControllerAction>
</ControllerAction>
```

`OpenScenarioParser.get_controller()` 解析此节点后，由 `ChangeActorControl` 原子在运行时实例化并调用。

### 5.3 AgentWrapper 的作用

`AgentWrapper`（`srunner/autoagents/agent_wrapper.py`）：
1. **`setup_sensors(vehicle)`**：读取 `agent.sensors()` 列表，在 CARLA 世界中 spawn 对应传感器（相机/激光雷达/GNSS），并注册回调将数据写入 `agent.sensor_interface`
2. **`__call__()`**：每帧调用 `agent()` → `agent.run_step(input_data, timestamp)` → 返回 `VehicleControl`

### 5.4 每帧执行

```python
# scenario_manager_local.py: _tick_scenario()
if self._agent is not None:
    ego_action = self._agent()                          # ADS 决策
    self.ego_vehicles[0].apply_control(ego_action)      # 下发控制指令
```

**当前 demo 无 ADS**：`agent_instance = None`，ego vehicle 的行为完全由 `.xosc` 中定义的 `<RoutingAction>` 和内置控制器驱动。

## 六、场景停止逻辑

### 6.1 正常停止：py_trees 行为树

`ScenarioManager.run_scenario()` 主循环：

```python
while self._running:
    snapshot = world.get_snapshot()
    self._tick_scenario(snapshot.timestamp)
```

`_tick_scenario()` 中每帧调用 `self.scenario_tree.tick_once()`。
当行为树状态变为非 `RUNNING`（即 `SUCCESS` 或 `FAILURE`）时：

```python
if self.scenario_tree.status != py_trees.common.Status.RUNNING:
    self._running = False  # 退出主循环
```

**停止触发来源**：
- `.xosc` 中 `<Act>` 的 `<StopTrigger>` 条件满足（如到达终点、超时、碰撞等）
- `<Storyboard>` 顶层 `<StopTrigger>` 中以 `criteria_` 开头的条件（测试标准）

### 6.2 超时停止：Watchdog

```python
self._watchdog = Watchdog(float(self._timeout))  # timeout 默认 10s（心跳超时）
self._watchdog.start()
# 每帧 _tick_scenario 中调用 self._watchdog.update() 重置计时器
```

若某帧超过 timeout 未 tick，Watchdog 触发异常，防止仿真卡死。

**注意**：`OpenScenario` 实例化时传入 `timeout=100000`（场景运行超时），与 Watchdog 的心跳超时不同。

### 6.3 信号中断停止

捕获 `SIGINT`/`SIGTERM`/`SIGHUP`：

```python
def _signal_handler(self, signum, frame):
    self._shutdown_requested = True
    self.manager.stop_scenario()   # 设置 _running = False
    self._cleanup()
```

### 6.4 清理流程

`_cleanup()` 执行顺序：
1. 重置 CARLA world 为异步模式
2. `manager.cleanup()` → 停止 Watchdog、终止 scenario、清理 agent
3. `CarlaDataProvider.cleanup()` → 清除 Actor 缓存
4. 逐一销毁 ego_vehicles
5. 销毁 `agent_instance`

## 七、指标收集

### 7.1 DataCollector（自定义收集器）

**文件**：`src/data_collector.py`

每帧由 `ScenarioManager._tick_scenario()` 调用 `data_collector.collect_frame_data()`。

**收集内容**：

| 数据类别 | 字段 |
|----------|------|
| 场景元信息 | 场景名、地图名、起始坐标、天气（cloudiness/precipitation/wind/fog）、开始时间戳 |
| 每帧 Actor 数据 | Actor ID、类型、位置(x/y/z)、旋转(pitch/yaw/roll)、速度(x/y/z)、加速度 |
| 车辆控制 | throttle、steer、brake、hand_brake、reverse（仅 vehicle 类型） |
| 汇总统计 | 总帧数、总时长（秒）、平均帧率 |

**保存格式**：JSON，默认路径 `./eval/collected_data_{场景名}_{时间戳}.json`

**数据结构**：
```json
{
  "scenario_info": { "scenario_name": "...", "town_name": "...", "weather": {...}, ... },
  "frames": [
    {
      "frame": 0,
      "timestamp": 1234567890.0,
      "simulation_time": 0.05,
      "actors": [
        {
          "id": 42, "type": "vehicle", "type_id": "vehicle.tesla.model3",
          "location": {"x": ..., "y": ..., "z": ...},
          "rotation": {"pitch": ..., "yaw": ..., "roll": ...},
          "velocity": {"x": ..., "y": ..., "z": ...},
          "control": {"throttle": ..., "steer": ..., "brake": ...},
          "is_hero": true
        }
      ]
    }
  ],
  "summary": { "total_frames": 400, "duration_seconds": 20.0, "fps": 20.0 }
}
```

### 7.2 atomic_criteria（场景评测标准）

**文件**：`srunner/scenariomanager/scenarioatomics/atomic_criteria.py`

这些指标以 py_trees 行为节点形式在场景树中运行，每帧 `update()` 更新状态。

| 类名 | 指标 | 单位 |
|------|------|------|
| `CollisionTest` | 碰撞次数 | 次 |
| `MaxVelocityTest` | 最大速度是否超限 | m/s |
| `DrivenDistanceTest` | 行驶总里程 | 米 |
| `AverageVelocityTest` | 平均速度 | m/s |

每个 Criterion 的状态为 `INIT` → `RUNNING` → `SUCCESS` / `ACCEPTABLE` / `FAILURE`。

在 `.xosc` 的 `<StopTrigger>` 中，以 `criteria_` 开头的 `<Condition>` 会被识别为评测标准（`_create_test_criteria()`），加入场景树并行执行。

### 7.3 场景结果分析

`ScenarioManager.analyze_scenario()` 汇总所有非 optional criteria：
- 所有标准通过 → **SUCCESS**
- 有超时无失败 → **TIMEOUT**
- 有非 optional 标准失败 → **FAILURE**

## 八、完整调用链

```
demo.py: main()
│
├─ DataCollector(scenario_name)                         # 创建收集器
│
└─ ScenarioRunner(args, xml_tree)
     │
     └─ run() → _run_openscenario()
          │
          ├─ OpenScenarioConfiguration(xml_tree, ...)   # 解析 .xosc
          │    ├─ XSD 校验
          │    ├─ 参数替换
          │    ├─ Catalog 加载
          │    ├─ 地图加载 / 切换
          │    └─ Actor 信息提取（位置/速度/类型）
          │
          └─ _load_and_run_scenario(config)
               ├─ _load_and_wait_for_world(town)         # 加载地图，设同步模式
               ├─ _prepare_ego_vehicles()                # Spawn ego 车辆
               ├─ OpenScenario(world, ego_vehicles, ...) # 构建行为树
               │    ├─ _initialize_actors()              # Spawn other actors
               │    ├─ _create_init_behavior()           # 初始位置/速度/路线/控制器
               │    ├─ _create_behavior()                # Story/Act/Maneuver 行为树
               │    └─ _create_test_criteria()           # criteria_ 评测节点
               │
               ├─ manager.load_scenario(scenario)        # 挂载行为树到 manager
               ├─ data_collector.initialize(world, hero) # 收集器初始化
               │
               └─ manager.run_scenario()                 # 主循环
                    │  while _running:
                    │    tick_scenario(timestamp)
                    │      ├─ GameTime.on_carla_tick()
                    │      ├─ CarlaDataProvider.on_carla_tick()
                    │      ├─ agent() → apply_control()  # ADS 决策（若有）
                    │      ├─ scenario_tree.tick_once()  # 驱动行为树
                    │      ├─ data_collector.collect_frame_data()  # 收集数据
                    │      └─ 检查 tree.status → 非 RUNNING 则退出
                    │
                    └─ 退出后 scenario.remove_all_actors()
```
